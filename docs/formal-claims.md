# Formal Claims

Status values are intentionally narrow: `Proven`, `Tested`, `Asserted`, or
`Aspirational`. Every row names the code boundary, evidence, bound, model gap,
and revisit trigger.

Every row carries a `layer`: `capability`, `loader`,
`runtime-determinism`, `memory-isolation`, `ipc`, `scheduling`,
`syscall-boundary`, or `fault-containment`. `scripts/check-formal-claims.py`
rejects an unknown layer and requires at least one row per layer.

Every row also carries a `platform` column (last): `n/a` for a claim
with no hardware dependence, otherwise `<class> PB-ID[, PB-ID...]` citing rows
of `docs/platform-boundary-contracts.md`. The class says whether the claim is
read as `production`, `qemu-only`, or `fixture` evidence;
`scripts/check-platform-boundary-contracts.sh` rejects a `production` class that
cites any non-production contract.

Each `make check-formal` gate also writes `build/certs/<gate>.json` (tool and
version, `HEAD` commit, dirty flag, UTC time, result, and the assertions the
gate script observed in its own tool output). Certificates are untracked
(`build/` is ignored), so a gate run never dirties the tree.
`python3 scripts/gate_cert.py verify` accepts the set only when every gate's
certificate has commit equal to `HEAD` and a clean tree;
`scripts/build-evidence-kit.sh` regenerates them on a clean tree, requires
that, and copies them to `build/evidence/certs/`. `make check-gate-cert`
tests the verifier against stale, dirty, and missing certificates.
