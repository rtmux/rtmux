# SMP Invariants

This ledger is the row-level companion to `docs/smp-contract.md`. Each shared
object family names the synchronization rule that owns mutation, the
interrupt/preemption rule while that state is unstable, and the cross-hart wake
or reclamation rule that makes the invariant observable under SMP.

| object family | lock, RCU, or atomic rule | interrupt and preemption rule | cross-hart wake or teardown rule | evidence |
| --- | --- | --- | --- | --- |
| process_t | Publish and remove process-vector slots under `process_vector_slock`; scalar thread-vector mutation uses `process_t.vec_slock`; RCU lookups must promote through `process_pin()` before use beyond the read section. | Do not block or call `rcu_sched_synchronize()` while a spinlock is held; process teardown waits outside deadline paths. | Unpublish from the vector, wait for `process_rcu`, revoke caps naming the process, drain pins, then return the soul. | `kernel/ext/process.c`; `kernel/sync/rcu.c`; `make check-rcu-sched`; `CPUS=8 scripts/qemu-regress.sh --mode rcu-lookup-measure --timeout 420` |
| thread_t | Thread-vector membership is protected by `process_t.vec_slock`; runqueue membership is protected by the target `kdispatch_t.lock`; thread scalar fields use `LOCK_CLASS_THREAD` or atomics such as `async_flags`. Every write to `thread_t.flags` (`RTMUX_FLG_THR_*`) is an `atomic_or`/`atomic_clr`, because any hart may set a bit on a thread running elsewhere; `async_flags` is the only cross-hart request word (`RTMUX_ATF_CANCEL` asks the owning hart to redirect a cancelled thread, so only the owner rewrites its registers). | A thread may be on one runqueue or running on one hart, never both; queue publication precedes state/bridge-bit release with `cpu_smp_mb()`. | Remote readying targets the destination dispatch lock and sends reschedule IPIs through `smp_resched()` when the target hart must preempt. | `kernel/thread/lifecycle.c`; `kernel/sched/dispatch.c`; `arch/riscv/cpu-misc.c`; `CPUS=8 scripts/qemu-regress.sh --mode preempt-latency --timeout 180` |
| cap table | Capability slots are mutated only by cap-table helpers; generation and type checks must precede object use; revocation marks matching slots dead before object memory is reusable. | Cap-table scans and transfer validation stay bounded by fixed slot/vector limits and do not sleep while holding table state. | Object teardown calls the revoke path before free; stale handles fail after detach, revoke, or generation change on any hart. | `kernel/cap/table.c`; `docs/capability-law.md`; `make check-capability-law`; `CPUS=8 scripts/qemu-regress.sh --mode revoke-stress --timeout 120` |
| channel/connect | `process_t.vec_slock` finds objects; `channel_t.lock` owns receive/reply queues; `connect_t.lock` owns send-side connection state; order is `PROCVEC`, `CHANNEL`, `CONNECT`. | Drop channel/connect locks before scheduler block/ready operations except for documented release-and-block handoff points. | Destroy unpublishes lookup state, wakes or errors waiters, waits for `connobj_rcu`, and revokes endpoint caps before connection storage can be reused. | `kernel/ipc/channel.c`; `kernel/ipc/connect.c`; `kernel/ipc/message.c`; `make check-lock-rank`; `CPUS=8 scripts/qemu-regress.sh --mode ipc-contention --timeout 180` |
| page tables | Address-space and page-table mutation uses the memory partition/page-table locks documented in `docs/smp-contract.md`; TLB-visible changes call the arch shootdown path. | Page-table mutation is not performed from hard IRQ; user-copy and fault paths must leave no lock held across unbounded IPC/server work. | `cpu_tlb_flush_complete()` performs the local `sfence.vma`, sends remote TLB shootdowns to live harts, and waits for completion before stale translations may be reused. | `arch/riscv/cpu-pte.c`; `kernel/ext/manipulate.c`; `docs/memory-objects-design.md`; `make check` |
| run queues | Each `kdispatch_t` owns one per-CPU ready set under `LOCK_CLASS_SCHED`; multiple dispatch locks are taken in stable hart-id/address order. | Ready/unready/select keep interrupts disabled only for bounded queue mutation; scheduling state is published before returning to U-mode. | Remote readying compares priority/runmask, queues on the target dispatch, and sets `RTMUX_ATF_SMP_RESCHED` or sends an IPI when the remote hart must reschedule. | `kernel/sched/dispatch.c`; `arch/riscv/trap-handler.c`; `make check-lock-rank`; `CPUS=8 scripts/qemu-regress.sh --mode preempt-latency --timeout 180` |
| RCU lookups | RCU read sections wrap vector/object lookup only; readers must not block; writers unpublish first and free only after `rcu_sched_synchronize()`. | Read sections are allowed in hot paths because they are compiler barriers; grace-period waits are non-deadline teardown work. | Quiescent states are published at context switch, U-mode return, dead-thread exit, idle entry, and final `in_kcall` zero transition. | `kernel/include/rcu.h`; `kernel/sync/rcu.c`; `scripts/check-rcu-sched.sh`; `CPUS=8 scripts/qemu-regress.sh --mode rcu-lookup-measure --timeout 420` |
| IRQ delivery | Interrupt metadata is protected by `LOCK_CLASS_INTREVENT`; hard IRQ handlers claim/mask/record and queue notification work without allocation or blocking. | Hard-IRQ code does not sleep, allocate, or take lower-rank subsystem locks; IST/user wakeup happens through bounded scheduler handoff. | Attached ISTs or notification endpoints are readied on the target dispatch and preempt via the same cross-hart reschedule path as IPC/timer wakeups. | `kernel/irq/interrupt.c`; `arch/riscv/trap-handler.c`; `docs/irq-contract.md`; `CPUS=8 scripts/qemu-regress.sh --mode preempt-latency --timeout 180` |
| timers | Timer object/queue mutation uses `LOCK_CLASS_TIMER`; timer callbacks do only bounded wakeup work and hand off to scheduler locks through documented paths. | Timer interrupt work cannot allocate, block, or run unbounded callbacks while the timer lock is held. | Cross-hart timer wakeups ready the target thread and request reschedule if the target hart is running lower-priority work. | `kernel/time/timer-core.c`; `kernel/time/clock-core.c`; `CPUS=8 scripts/qemu-regress.sh --mode rt-check --timeout 180`; `CPUS=8 scripts/qemu-regress.sh --mode preempt-latency --timeout 180` |
| revoke paths | Object-specific teardown calls cap/object revoke before storage reuse; pinned objects are freed only after pin and RCU drains complete. | Revoke scans are bounded by fixed cap-table and process-vector limits; no scheduler blocking while object locks or vector locks are held. | Waiters and stale holders observe denial through generation/type/right checks after revoke; endpoint detach under sender churn must not strand unrelated IPC. | `kernel/cap/table.c`; `kernel/ipc/connect.c`; `kernel/ext/process.c`; `CPUS=8 scripts/qemu-regress.sh --mode revoke-stress --timeout 120` |

Run `make check-smp-invariants` after changing any row's synchronization rule.
The QEMU half is `CPUS=8 scripts/qemu-regress.sh --mode smp-invariants
--timeout 180`, a bounded smoke over lock-rank, RCU lookup, revoke, preemption,
and IPC-contention paths. On reference-host, the heavy release gate remains `CPUS=8 make
check check-rt` plus the standalone formal gates and full per-mode benchmarks
available in that environment.
